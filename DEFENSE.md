## Показ отладки в IDE

1. Поставить точку останова на строке return в get_next_watering.
2. Запустить main.py в режиме отладки.
3. Посмотреть last_watering и interval. Интервал равен 7.
4. Выполнить строку пошагово. К дате последнего полива прибавится 7 дней.
5. Временно заменить плюс на минус в этой строке.
6. Повторить отладку. Дата окажется раньше последнего полива.
7. Исправить минус на плюс и снова запустить программу.
8. Не сохранять ошибочный вариант в Git.

Пример для 9 сентября 2026 года: последний полив 2 сентября,
правильная следующая дата — 9 сентября, ошибочная — 26 августа.
Эта ошибка проверена через встроенный отладчик Python pdb в рабочей среде.
Показ отладчика IDE на своем компьютере нужно выполнить отдельно.

## Git после самостоятельных изменений

```bash
git status
git add main.py README.md .gitignore test_main.py
git commit -m "Обновить проект ПР1"
git log --oneline
git push
```

Commit нужен только при наличии новых изменений.

## Ответы на контрольные вопросы

1. Основные типы: int, float, str, bool. Также есть списки, словари и другие типы.
2. int — целое число, float — дробное, str — строка, bool — True или False.
3. Преобразование меняет тип значения, например int("7") дает число 7.
4. Строки можно соединять, повторять, сравнивать, получать их части.
5. Операторы сравнения: ==, !=, >, <, >=, <=.
6. if выполняет код, когда условие верно.
7. if проверяет первое условие, elif — следующее, else работает, если условия не подошли.
8. Составные условия записывают через and, or и not, при необходимости со скобками.
9. and требует выполнения обоих условий, or — хотя бы одного, not меняет результат на противоположный.
10. Модуль — файл с кодом Python, который можно подключить к программе.
11. import подключает модуль, чтобы использовать его возможности.
12. После import datetime пишут datetime.date. После from datetime import date можно писать просто date.
13. Виртуальное окружение хранит отдельный набор библиотек для проекта.
14. IDE — программа, в которой удобно писать, запускать и проверять код.
15. Git сохраняет историю изменений проекта.
16. Репозиторий — хранилище файлов проекта и их истории.
17. Commit — сохраненная версия изменений с сообщением.
18. .gitignore задает файлы, которые Git не должен добавлять. Уже добавленные файлы он из истории не удаляет.
19. README.md объясняет, что это за проект и как его запустить.
20. Отладка — поиск причин ошибок во время выполнения программы.
21. Breakpoint — точка, где отладчик останавливает выполнение.
22. Пошаговый запуск помогает увидеть, какая строка меняет переменную неправильно.
23. Приложение помогает вовремя ухаживать за растениями.
24. Пользователи — люди, выращивающие растения дома, в офисе или на даче.
25. Основные сущности: пользователь, растение, вид растения, уход, напоминание, запись об уходе.
26. Планируются добавление растений, напоминания, фотографии, история ухода и учетные записи.
27. Сейчас показан уход за одним фикусом: расчет даты полива, проверка срока и отметка полива.
28. Использованы простые типы, преобразование int, условия, функции, операции с датами и импорт datetime.
29. После ООП появятся классы, после Django — страницы сайта, база данных и пользователи.
30. У разных людей есть свои растения и записи об уходе. Их удобно хранить в базе и просматривать через сайт.
